#  02 — MicroK8s Cluster Automation with Ansible

## Overview

After Terraform creates the VMs, Ansible brings up the full Kubernetes cluster.
The main playbook (`playbook.yml`) runs 6 plays in order, each targeting a
different group of hosts.

**Files:**
```
micro_k8s/ansible/
├── playbook.yml              # Master orchestration
├── ansible.cfg               # SSH + privilege settings
├── inventory.ini             # Auto-generated by Terraform
├── group_vars/all.yml        # Shared variables for all hosts
├── metallb-pool.yaml         # MetalLB IP pool manifest
└── roles/
    ├── common/               # Every node
    ├── master/               # Control plane only
    ├── worker/               # Worker nodes (serial)
    ├── longhorn/             # Storage (all nodes)
    ├── gitlab/               # GitLab VM
    └── juju/                 # Juju VM
```

---

## Ansible Configuration (`ansible.cfg`)

```ini
[defaults]
remote_user = ubuntu
host_key_checking = False
forks = 5

[privilege_escalation]
become = True
become_method = sudo

[ssh_connection]
ssh_args = -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null
pipelining = True
```

`pipelining = True` reduces SSH round-trips by sending multiple commands
through a single SSH connection — significantly speeds up playbook execution.

## Shared Variables (`group_vars/all.yml`)

```yaml
network:
  control_ip: "10.110.188.144"
  dns_servers: [8.8.8.8, 1.1.1.1]
  pod_cidr:     "172.16.1.0/16"
  service_cidr: "172.17.1.0/18"

software:
  kubernetes: "1.31.0-*"
  calico:     "3.26.0"

controlplane:
  name: controlplane
  ip:   "10.110.188.144"

workers:
  - { name: node01, ip: "10.110.188.145" }
  - { name: node02, ip: "10.110.188.146" }
```

These variables are imported by every role.  The `workers` list is used to
populate `/etc/hosts` on every node so hostnames resolve without DNS.

## Play 1 — Common Setup (all K8s nodes)

**Role:** `roles/common/tasks/main.yml`  
**Target:** `k8s` (controlplane + both workers)

### What it does, step by step

**1. Install system packages**
```
curl, ca-certificates, apt-transport-https, gnupg,
jq, snapd, iptables, software-properties-common
```

**2. Configure DNS via systemd-resolved**
Creates `/etc/systemd/resolved.conf.d/dns_servers.conf` pointing to
`8.8.8.8` and `1.1.1.1`.  Restarts `systemd-resolved`.

**3. Populate `/etc/hosts`**
Adds entries for the controlplane and all workers so that Kubernetes components
can resolve node names without relying on external DNS.

**4. Disable swap**
```bash
swapoff -a                    # immediate
# comments out swap lines in /etc/fstab  # persistent
```
Kubernetes requires swap to be off.  The kubelet will refuse to start if swap
is enabled.

**5. Kernel modules**
Writes `/etc/modules-load.d/k8s.conf`:
```
overlay       # container overlay filesystems
br_netfilter  # iptables on bridged traffic
ipip          # IP-in-IP tunneling for Calico
```
Loads each module immediately with `modprobe`.

**6. Sysctl parameters**
```
net.bridge.bridge-nf-call-iptables  = 1   # iptables sees bridged traffic
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1   # kernel routes between interfaces
fs.inotify.max_user_instances       = 1280
fs.inotify.max_user_watches         = 655360  # needed by many K8s controllers
```

**7. Install MicroK8s 1.31/stable**
```bash
snap install microk8s --classic --channel=1.31/stable
```
5 retries with 10s delay — snap downloads can be flaky.

**8. User permissions**
Adds `ubuntu` to the `microk8s` group so commands work without sudo.

**9. Wait for MicroK8s**
```bash
microk8s status --wait-ready
```
Blocks until the cluster is fully initialised.

**10. Shell aliases**
Adds `kubectl='microk8s kubectl'` and `helm='microk8s helm'` to both
`ubuntu` and `root` `.bashrc`.

## Play 2 — Control Plane Setup

**Role:** `roles/master/tasks/main.yml`  
**Target:** `master` (controlplane only)

### kubectl wrapper
Creates `/usr/local/bin/kubectl` as a shell script:
```sh
#!/bin/sh
exec /snap/bin/microk8s.kubectl "$@"
```
This means any tool that calls `kubectl` (like the Admin Portal) works without
knowing about the snap path.

### Enable addons
```bash
microk8s enable dns
microk8s enable metallb:10.110.188.200-10.110.188.207
```

### Configure Calico for IP-in-IP

By default MicroK8s uses Calico in VXLAN mode.  We switch to IP-in-IP for
lower overhead on the LAN:
```bash
kubectl patch configmap calico-config -n kube-system \
  --type merge -p '{"data":{"calico_backend":"bird"}}'

kubectl patch ippool default-ipv4-ippool \
  --type merge -p '{"spec":{"vxlanMode":"Never","ipipMode":"Always"}}'

kubectl set env daemonset/calico-node -n kube-system \
  CALICO_IPV4POOL_VXLAN=Never CALICO_IPV4POOL_IPIP=Always

kubectl rollout restart daemonset calico-node -n kube-system
```

### Kubeconfig generation
```bash
microk8s config    # outputs the kubeconfig YAML
```
Written to three places:
- `configs/config` (local Ansible controller — for other plays to use)
- `/root/.kube/config` (control plane root user)
- `/home/ubuntu/.kube/config` (control plane ubuntu user)

### Helm installation
```bash
curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash
```

### Node labelling
```bash
kubectl label node $(hostname) \
  node-role.kubernetes.io/control-plane="" \
  node-role.kubernetes.io/master="" --overwrite
```

## Play 3 — Worker Nodes Join (serial: 1)

**Role:** `roles/worker/tasks/main.yml`  
**Target:** `workers`  
**Serial:** 1 (one worker at a time — prevents token collisions)

### Idempotency check
Before trying to join, the role checks if the node is already in the cluster:
```bash
kubectl get nodes -o jsonpath='{.items[*].metadata.name}'
```
If `inventory_hostname` appears in the output, `is_joined: true` and the join
steps are skipped.

### Join process
```bash
# On master (delegated):
microk8s add-node --token-ttl 600
# Outputs: microk8s join 10.110.188.144:25000/<token>

# On worker:
microk8s join 10.110.188.144:25000/<token> --worker
```
3 retries, 10s delay — join tokens can take a moment to become valid.

### Post-join
- Labels the node as `worker` (delegated to master)
- Copies kubeconfig from `configs/config` to ubuntu and root users

## MetalLB Pool (`metallb-pool.yaml`)

```yaml
apiVersion: metallb.io/v1beta1
kind: IPAddressPool
metadata:
  name: kubeflow-pool
  namespace: metallb-system
spec:
  addresses:
  - 10.110.188.200-10.110.188.207
---
apiVersion: metallb.io/v1beta1
kind: L2Advertisement
metadata:
  name: l2-advert
```

MetalLB is an in-cluster load balancer.  When Kubeflow's Istio Ingress Gateway
service requests a `LoadBalancer` IP, MetalLB assigns `.200` from this pool and
sends ARP responses on the LAN, making the Kubeflow dashboard reachable at
`http://10.110.188.200` from any machine on the network.

## Running the Playbook

```bash
cd micro_k8s/ansible

# Full run
ansible-playbook playbook.yml -i inventory.ini

# Only specific layers
ansible-playbook playbook.yml -i inventory.ini --tags common,kubernetes
ansible-playbook playbook.yml -i inventory.ini --tags master
ansible-playbook playbook.yml -i inventory.ini --tags longhorn
ansible-playbook playbook.yml -i inventory.ini --tags gitlab
ansible-playbook playbook.yml -i inventory.ini --tags juju

# Single host
ansible-playbook playbook.yml -i inventory.ini --limit controlplane
```

## Key Design Decisions

| Decision | Reason |
|---|---|
| MicroK8s instead of kubeadm | Single snap install, built-in addon system, minimal config |
| Calico IP-in-IP (not VXLAN) | Lower encapsulation overhead on a flat LAN |
| Serial: 1 for workers | Avoids simultaneous `add-node` token generation conflicts |
| kubeconfig copied to `configs/` | Other plays (GitLab portal, Juju) need it without re-running master role |
| MetalLB L2 mode | No BGP router required — ARP-based on a flat LAN works reliably |
